Notifikasi Transaksi di Laptop (Web Push)

Spesifikasi DEAR-100 (inisiatif DEAR-97), revisi 29 Okt 2026: kanal notifikasi browser/sistem lewat Web Push dari dashboard (menggantikan versi Telegram). Dua deliverable: (A) teks & perilaku notifikasi sistem final untuk Backend, (B) layar Pengaturan → Notifikasi gaya Arah A "Jus Hangat" (token sama dengan owner.html & owner-dark.html, tanpa token baru). Aplikasi kasir tidak berubah.

A. Notifikasi sistem

A.1 Prinsip & batas

  • Judul = inti (emoji + jenis + nominal), ≤ 40 karakter; isi ≤ 2 baris, ≤ 45 karakter per baris. Windows memotong dengan "…", macOS lebih sempit; baris 1 judul harus sudah cukup.
  • Browser menambah sendiri nama aplikasi/situs; jangan diulang di teks. Rupiah Rp45.000; jam 14.32 WIB (zona toko); kode #TRX-0123.
  • Tanpa PIN, token, data pelanggan, alasan void (teks bebas), atau referensi pembayaran. Nama kasir = nama tampil pegawai saja. Notifikasi bisa terlihat orang lain di layar laptop, jadi hanya angka ringkas.
  • Teks final di tabel A.3; mengubahnya = ubah dokumen ini dulu. Bahasa Indonesia tetap.

B. Layar Pengaturan → Notifikasi

B.1 Penempatan & susunan

  • Halaman /pengaturan/notifikasi, sub-item Notifikasi di bawah Pengaturan (sidebar desktop / sheet Lainnya di HP). Hanya role owner.
  • Tiga kartu berurutan: Notifikasi di browser ini (status izin + aksi), Perangkat terdaftar (daftar + Cabut), Jenis notifikasi (dua toggle, tersimpan otomatis; toast "Tersimpan"; gagal → nilai kembali + toast "Gagal menyimpan. Coba lagi.").
  • Toggle berlaku per akun owner untuk semua browser terdaftar (bukan per browser); terkunci sebelum ada minimal satu browser aktif di akun.
  • Izin tidak pernah diminta saat halaman dimuat; hanya setelah klik "Aktifkan notifikasi di browser ini".

B.2 Belum aktif (izin belum diminta)

Satu aksi utama. Penjelasan batasan (browser harus berjalan, laptop tidur menahan notifikasi).

B.5 Diblokir di browser

Terdeteksi dari Notification.permission === 'denied'. Tidak ada tombol aktifkan (tidak berguna); tampil panduan membuka blokir untuk Chrome/Edge dan macOS (juga Windows), plus "Muat ulang halaman". Perubahan izin dideteksi via navigator.permissions.query({name:'notifications'}).onchange agar layar ikut berubah tanpa muat ulang.

C. Catatan untuk Frontend

  • Komponen baru: Switch (role="switch", 52×32, target ≥44px, label via aria-labelledby, Spasi mengubah), Lainnya: Card, Button, Badge, ConfirmDialog yang ada. Token: semua dari tema yang ada; tombol utama pakai pri-ink.
  • Service Worker di root (/sw.js) agar scope seluruh dashboard; hanya menangani push dan notificationclick. Jangan cache aset di SW ini.
  • Status memakai ikon + teks; perubahan lewat role="status", galat role="alert"; fokus berpindah ke kartu saat panduan terbuka. Kontras mengikuti DEAR-90.
  • Responsif: ≥1024 konten maks 720px; <768 satu kolom, tombol utama lebar penuh (min 48). Di HP layar yang sama dipakai; fitur utama di laptop.
  • Teks UI: "pembatalan", bukan "void" (selaras DEAR-66). Hitung klik mengaktifkan: Aktifkan → Izinkan = 2 klik.

E. Asumsi & hal terbuka

  • Pemakai utama: owner di laptop dengan Chrome/Edge (Windows/macOS). Safari macOS dan HP tidak dirancang khusus di tahap ini.
  • Alasan void sengaja tidak ditampilkan (teks bebas bisa memuat data pelanggan).
  • Void disetujui oleh owner sendiri tetap dikirim ke semua browser terdaftar (sederhana; bisa dilewati untuk browser pemberi persetujuan bila dirasa mengganggu).
  • Void ditolak, shift, dan rekap harian tidak termasuk (potongan pertama).
  • Logo/ikon 192px dan badge 96px perlu disiapkan (saya bisa membuatnya sebagai SVG→PNG bila diminta); sementara mockup memakai emoji 🍊.
  • Gambar notifikasi OS di mockup meniru Windows 11 dan macOS; tampilan asli ditentukan sistem operasi. Nama situs pada header ("Google Chrome · Kelola Kasir") ditambahkan browser, bukan kita.
  • TTL 4 jam dan ambang batch > 3 adalah konstanta Backend.

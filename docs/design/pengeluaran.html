Pemilih cabang + Pengeluaran & Rekap bulanan

DEAR-135 · Revisi 2 (review Owner) · Induk: konsep catatan pengeluaran per cabang. Gaya Arah A · Jus Hangat (token = apps/dashboard/src/styles.css), terang + gelap, desktop (≥1024) + HP (390). Semua mockup di bawah dirender dua kali: terang lalu gelap.

0. Asumsi & keputusan desain (untuk Frontend/Tech Lead)

  • Pengguna utama: owner (Albert/investor) di HP, sering sambil belanja di pasar/toko → form harus ≤ 20 detik, satu tangan, tanpa keyboard penuh bila bisa.
  • Ganti cabang = switch-outlet (ADR-0020, PR #91). Memilih cabang memanggil switch-outlet: server mengeluarkan token baru dan klien membersihkan seluruh cache. Klien tidak mengirim outlet_id per request. Cabang aktif mengikuti token (bukan state lokal). Login pertama: pilih cabang terakhir; jika baru, tampilkan sheet pilih cabang (tidak ada default diam-diam).
  • State loading ganti cabang (baru): selama switch-outlet berjalan (biasanya < 1 dtk) pil cabang menampilkan spinner + "Mengganti ke Palmerah…" dan tidak bisa diketuk; isi halaman diganti kerangka (skeleton) karena cache dibuang, data cabang lama tidak pernah ditampilkan; tombol Tambah nonaktif. Gagal: pil kembali ke cabang semula + banner "Gagal ganti cabang. Cabang tetap Ragunan. Coba lagi."
  • "Semua cabang" hanya ada di Pengeluaran dan Rekap (hanya baca; tombol Tambah nonaktif). Di halaman lain (Ringkasan, Transaksi, Produk, Shift, Pegawai, Perangkat, Pengaturan) opsi ini tidak ada di menu pemilih. Berpindah dari Pengeluaran/Rekap (Semua cabang) ke halaman lain otomatis kembali ke cabang terakhir (switch-outlet + loading singkat) dan muncul toast "Kembali ke Ragunan. Semua cabang hanya ada di Pengeluaran dan Rekap." Asumsi untuk Tech Lead: "Semua cabang" juga dilayani lewat switch-outlet (mode lintas-cabang, baca saja); mohon konfirmasi bentuk token/respons.
  • Peran Manager (baru): manager hanya melihat cabangnya. Pemilih cabang terkunci: pil berisi kode + nama cabang + ikon gembok, tanpa panah, tidak bisa diketuk, tanpa opsi "Semua cabang". Rekap tanpa perbandingan 2 cabang. Tombol Hapus (di form Ubah) dan menu Kelola kategori tidak dirender (bukan disabled). Manager tetap bisa Tambah dan Ubah. Penegakan sebenarnya tetap di API (UI hanya menyembunyikan). Asumsi: manager juga tidak melihat menu Pengaturan (field tanggal mulai khusus owner); mohon Owner konfirmasi bila manager perlu Pengaturan lain.
  • Tanggal mulai operasional cabang (DEAR-140): Rekap dihitung mulai tanggal ini per cabang. Keterangan selalu tampil di Rekap ("Dihitung mulai 3 Nov 2026"); di Semua cabang tampil per cabang. Field tanggal ada di Pengaturan → Cabang, khusus owner (layar 7). Mockup memakai Ragunan = 1 Okt 2026, Palmerah = 3 Nov 2026 hanya sebagai contoh; angka di mockup adalah ilustrasi. Asumsi: pengeluaran bertanggal sebelum tanggal mulai tetap tersimpan dan tampil di daftar, tapi tidak dihitung di Rekap (mohon Owner/Tech Lead konfirmasi); bulan yang seluruhnya sebelum tanggal mulai tampil state kosong.
  • Identitas cabang tidak hanya warna: kode 3 huruf (RGN/PLM) + nama + garis warna 5px di bawah header (Ragunan = oranye tua, Palmerah = biru, Semua = garis putus-putus netral). Kontras ≥ 4.5:1 terang/gelap. Token tambahan hanya --rgn-* / --plm-* (pakai nilai tint/info yang sudah ada).
  • Form tambah: cabang terkunci ke cabang aktif (ditampilkan sebagai chip, bisa diubah hanya lewat pemilih header, bukan di form). Tanggal default hari ini; sumber dana default = pilihan terakhir; kategori = 8 kategori terakhir/terbanyak dipakai di baris atas (grid ikon, 1 tap).
  • Target tap tambah pengeluaran (kasus tipikal): Tambah(1) → kategori(1) → ketik nominal (keypad angka, 1 field) → Simpan(1) = 3 tap + nominal. Keterangan & foto opsional; keterangan otomatis terisi nama kategori bila kosong.
  • Nominal: input angka-saja (inputmode="numeric"), tampil Rp 1.250.000 dengan pemisah titik; Rupiah bulat, maks 999.999.999; tombol cepat +10rb/+50rb/+100rb tidak dipakai (rawan salah); tersedia kalkulator tidak.
  • Foto nota: kamera langsung (capture="environment") atau galeri; dikompres ≤ 200 KB di klien; tampil thumbnail + Ganti/Hapus.
  • Hapus pengeluaran = konfirmasi dialog + alasan opsional; soft delete (tampil di Riwayat Hapus). Edit mengikuti form yang sama (judul "Ubah pengeluaran", tombol Simpan perubahan).
  • Rekap: Laba sederhana = Omzet − Pengeluaran, bukan laba akuntansi; label "Laba sederhana" + ikon info (tooltip: "Omzet dikurangi semua pengeluaran yang dicatat sejak tanggal mulai"). Omzet = definisi sama dengan Ringkasan dashboard: transaksi lunas + yang masih menunggu persetujuan batal; batal yang sudah disetujui dan transaksi terhapus tidak dihitung.
  • Pengeluaran sumber Uang owner tetap dihitung di pengeluaran/laba (kas laci tidak berubah di Fase 1); badge sumber ditampilkan di daftar agar jelas.
  • Kategori bawaan terkunci dari hapus (hanya Nonaktifkan/ganti nama); kategori nonaktif tidak muncul di form tapi tetap muncul di data lama. Kelompok (Bahan jus/Operasional/Tetap/Lainnya) tidak bisa diubah owner.

Breakpoint & perilaku

  • ≥1024: sidebar 220px + header dengan pemilih cabang (kiri judul, kanan pemilih). 768–1023: sidebar ikon. <768: bottom-tab (Ringkasan · Transaksi · Pengeluaran · Menu), pemilih cabang di header kiri; membuka bottom sheet.
  • Form: desktop = dialog 560px; HP = layar penuh/sheet tinggi dengan bar Simpan menempel bawah (56px).
  • Fokus keyboard terlihat (ring 3px --color-focus), semua target ≥44px, aksi utama 56px. Menu pemilih: role="listbox", Esc menutup, panah naik/turun.
